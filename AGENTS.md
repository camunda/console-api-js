## Repo-specific instructions

### Role & boundary

This repo builds `@camunda8/console-api`, the TypeScript client for the Camunda 8 SaaS Console (Administration) API. It is the reference implementation for the `console-api-<lang>` family; other languages follow its method names, configuration and transport behaviour.

It is **not** part of the Orchestration Cluster API SDKs. The Console API is the SaaS control plane, versioned independently of Camunda releases, so this package has its own version line and does not track the 8.x minor.

### Layout

- `spec/console-api.json` — committed, key-sorted snapshot of `https://console.cloud.camunda.io/customer-api/openapi/swagger.json`. `npm run generate` fetches the deployed spec into it first, as the OCA SDKs do; `CONSOLE_API_SPEC_OFFLINE=1` (`npm run generate:offline`) skips the fetch. CI and the release workflow are always offline, so only a committed, reviewed snapshot is published. `npm run spec:check` reports upstream drift (scheduled in CI). Upstream source: `apps/console-backend/src/routes/api/swagger.json` in the internal repo camunda/camunda-cloud-management-apps; the deployed copy differs only in `info` and `servers`, and `info.version` is not bumped on schema changes.
- `src/gen/` — generated by `@hey-api/openapi-ts` (`npm run generate`, or `generate:offline`). Never edit by hand. Committed; CI fails if regenerating from the committed spec changes it.
- `src/client.ts` — `ConsoleClient` facade. `OPERATION_METHODS` maps every spec operationId to a method; `tests/surface.test.ts` fails if any operation is unmapped or mis-routed.
- `src/transport.ts` — auth header, 401 refresh, retry policy. `src/auth.ts` — OAuth token provider. `src/config.ts` + `src/configSchema.ts` — `config: { CAMUNDA_* }` resolution. `src/errors.ts` — the `SdkError` union. `src/logger.ts` — leveled logging.

### Conventions

- **Ergonomics follow the OCA SDK of the same language** (`@camunda8/orchestration-cluster-api` for JS): argument style (one object per method, path and body fields merged, plus an optional trailing `{ retry }` options argument), config keys (`createConsoleClient({ config: { CAMUNDA_* } })`), error model (`SdkError` union + `isSdkError`), and the validation, retry and log settings (`CAMUNDA_SDK_VALIDATION`, `CAMUNDA_SDK_HTTP_RETRY_*`, `CAMUNDA_SDK_LOG_LEVEL`). When they differ, change this package. The other `console-api-<lang>` repos copy their own OCA SDK's style, not this one's.
- Facade method arguments: one object with path parameters and body fields merged. A field that is both a path parameter and a body field is a spec-level defect: `tests/surface.test.ts` checks every operation so a spec refresh cannot introduce one silently.
- New spec operation: add a method and an `OPERATION_METHODS` entry in the same PR as the spec refresh, then regenerate (`chore(gen): regenerate for ...` as a separate commit).
- Never retry non-idempotent methods (POST, PATCH) on 5xx or network errors; only 429 is safe for them.
- Schema validation failures are `ValidationSdkError` (side `request` or `response`), never an HTTP error, and never carry payload values: Console responses can contain connector secrets. Covered for every operation by `tests/validation-errors.test.ts`. The default validation is `req:strict,res:none` — stricter than OCA's `req:none,res:none`, on purpose (a malformed Console request can mutate SaaS resources).
- Errors and logs never carry payload values, response bodies or tokens at any level, including `silly` — unlike OCA, where `silly` logs bodies. `HttpSdkError.body` is the one documented exception (Console returns non-RFC error bodies); it is never interpolated into `message`.
- `User-Agent` is `camunda8-console-api-<lang>/<version>` on API and OAuth token requests, with `CAMUNDA_CUSTOM_USER_AGENT_STRING` appended after a space. This is the cross-language contract for the `console-api-<lang>` family. The JS version is injected at build time (tsup `define`), never read from `package.json` at runtime; `prepack` rebuilds and `scripts/check-dist-version.ts` verifies it after semantic-release sets the version.
- Environment variable names stay compatible with `@camunda8/sdk` (`CAMUNDA_CONSOLE_*`).

### Commands

- `npm run build` — generate (fetches the live spec unless `CONSOLE_API_SPEC_OFFLINE=1`), README snippet check, typecheck, lint, bundle.
- `npm test` — unit tests (no network).
- `npm run test:integration` — read-only checks against a real SaaS org with response validation on. Needs `CONSOLE_API_INTEGRATION=1` and `CAMUNDA_CONSOLE_CLIENT_ID`/`CAMUNDA_CONSOLE_CLIENT_SECRET`.
