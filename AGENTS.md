## Repo-specific instructions

### Role & boundary

This repo builds `@camunda8/console-api`, the TypeScript client for the Camunda 8 SaaS Console (Administration) API. It is the reference implementation for the `console-api-<lang>` family; other languages follow its method names, configuration and transport behaviour.

It is **not** part of the Orchestration Cluster API SDKs. The Console API is the SaaS control plane, versioned independently of Camunda releases, so this package has its own version line and does not track the 8.x minor.

### Layout

- `spec/console-api.json` — committed, key-sorted snapshot of `https://console.cloud.camunda.io/customer-api/openapi/swagger.json`. Refresh with `npm run spec:fetch`; `npm run spec:check` reports upstream drift (scheduled in CI).
- `src/gen/` — generated by `@hey-api/openapi-ts` (`npm run generate`). Never edit by hand. Committed; CI fails if regenerating from the committed spec changes it.
- `src/client.ts` — `ConsoleClient` facade. `OPERATION_METHODS` maps every spec operationId to a method; `tests/surface.test.ts` fails if any operation is unmapped or mis-routed.
- `src/transport.ts` — auth header, 401 refresh, retry policy. `src/auth.ts` — OAuth token provider. `src/config.ts` — options/env resolution.

### Conventions

- Facade method arguments: path parameters in URL order, then the request body. The surface test relies on this.
- New spec operation: add a method and an `OPERATION_METHODS` entry in the same PR as the spec refresh, then regenerate (`chore(gen): regenerate for ...` as a separate commit).
- Never retry non-idempotent methods (POST, PATCH) on 5xx or network errors; only 429 is safe for them.
- Schema validation failures are `ConsoleApiValidationError` (phase `request` or `response`), never an HTTP error, and never carry payload values: Console responses can contain connector secrets. Covered for every operation by `tests/validation-errors.test.ts`.
- `User-Agent` is `camunda8-console-api-<lang>/<version>` on API and OAuth token requests, with `userAgent` / `CAMUNDA_CUSTOM_USER_AGENT_STRING` appended after a space. This is the cross-language contract for the `console-api-<lang>` family. The JS version is injected at build time (tsup `define`), never read from `package.json` at runtime; `prepack` rebuilds and `scripts/check-dist-version.ts` verifies it after semantic-release sets the version.
- Environment variable names stay compatible with `@camunda8/sdk` (`CAMUNDA_CONSOLE_*`).

### Commands

- `npm run build` — generate, README snippet check, typecheck, lint, bundle.
- `npm test` — unit tests (no network).
- `npm run test:integration` — read-only checks against a real SaaS org with response validation on. Needs `CONSOLE_API_INTEGRATION=1` and `CAMUNDA_CONSOLE_CLIENT_ID`/`CAMUNDA_CONSOLE_CLIENT_SECRET`.
